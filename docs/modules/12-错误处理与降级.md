# 模块 12 — 错误处理与降级

> 状态：**v0.11 落地** / 优先级 P0（v0.11.0 一次性补齐 7 个核心类 + 45 例单测）

## 职责边界

全局错误码定义、错误分类、降级策略、用户可见的友好提示。
**禁止静默吞错**——所有错误必须让用户知道发生了什么、能做什么。

## 输入输出契约

```kotlin
@Serializable
sealed class AppError(
    open val code: ErrorCode,
    open val userMessage: String,
    open val technicalDetail: String,
    open val retryable: Boolean,
    open val suggestedAction: SuggestedAction? = null,
    override val cause: Throwable? = null,
) : RuntimeException(userMessage, cause) {
    data class Fatal(...) : AppError(...)  // 致命错误，App 无法继续运行
    data class Recoverable(...) : AppError(...)  // 可恢复错误，App 可继续运行
    companion object {
        fun of(...): AppError  // 默认 Recoverable
        fun fatal(...): AppError
    }
}

@Serializable
enum class ErrorCode {
    NETWORK, DNS, AUTH_401, AUTH_403,
    RATE_LIMIT_429, SERVER_5XX, TIMEOUT,
    OCR_LOW_CONFIDENCE, PARSE_LOW_CONFIDENCE,
    PERMISSION_DENIED, STORAGE_FULL, CONFIG_INVALID,
    UNCAUGHT, UNKNOWN,  // v0.11.0 新增 UNCAUGHT
}

@Serializable
enum class SuggestedAction { RETRY, CHECK_API_KEY, CHECK_NETWORK, OPEN_SETTINGS, CONTACT_SUPPORT }
```

## 关键类（v0.11.0 落地）

- `AppError`（`sealed class`，v0.11.0 从 `data class` 重构）— 统一错误类型
  - `AppError.Fatal`：致命错误，App 无法继续运行
  - `AppError.Recoverable`：可恢复错误，用户可见但 App 可继续运行
  - 工厂 `AppError.of(...)` / `AppError.fatal(...)` 保持向后兼容
- `ErrorClassifier`（`domain/error/ErrorClassifier.kt`）— Throwable → AppError 转换
  - 14 种 ErrorCode 全覆盖（v0.11.0 新增 `UNCAUGHT`）
  - 已分类的 `AppError` 透传不重复包装
  - 网络层用 `HttpException.code()` 分桶（401/403/429/5xx/其他）
- `ErrorPresenter`（`domain/error/ErrorPresenter.kt`）— AppError → UI model
  - 输出 `ErrorUiModel(title, message, action, actionLabel, retryable)`
  - 14 种 ErrorCode 全部有 title/message 兜底
- `CrashLogger`（`util/CrashLogger.kt`）— 本地脱敏崩溃日志
  - 写入 `filesDir/crash/yyyy-MM-dd-HH-mm-ss.txt`
  - 脱敏：`Bearer xxx` / `sk-xxx` / `sk_xxx` / `api_key=xxx` 全替换为 `***REDACTED***`
  - 栈超 200 行截断 + cause 链 5 层 + 老文件保留 20 个
- `GlobalErrorHandler`（`util/GlobalErrorHandler.kt`）— 全局线程异常处理
  - `Thread.setDefaultUncaughtExceptionHandler` 安装（链式调用保留旧 handler）
  - `onError: (ErrorUiModel) -> Unit` UI 回调（v0.11.0+ UI 接入）
- `CoroutineErrorHandler`（`util/CoroutineErrorHandler.kt`）— 协程异常处理工厂
  - 配合 `viewModelScope.launch(coroutineErrorHandler()) { ... }` 使用
- `DegradationManager`（`util/DegradationManager.kt`）— 4 维降级策略
  - 4 维：网络/OCR/内存/电池；3 档：NONE/MILD/SEVERE
  - 连续 3 次同轴升 MILD、连续 5 次升 SEVERE
  - 暴露 `pollMultiplier` / `streamEnabled` / `maxContextTokens` / `shouldDropHistory` 查询 API

## 错误码表（v0.11.0 完整 14 项）

| ErrorCode | 标题 | 完整文案 | retryable | suggestedAction |
|-----------|------|----------|-----------|-----------------|
| NETWORK | 网络问题 | 网络连接异常，请检查 WiFi 或移动数据后再试。 | 是 | CHECK_NETWORK |
| DNS | 网络问题 | 无法解析服务器地址，请检查「API URL」是否正确。 | 否 | CHECK_NETWORK |
| AUTH_401 | API Key 无效 | API Key 无效或已过期，请在「设置 → API」中重新填写。 | 否 | CHECK_API_KEY |
| AUTH_403 | 无权限访问 | 当前 API Key 无权访问该模型，请尝试切换到其他模型。 | 否 | CHECK_API_KEY |
| RATE_LIMIT_429 | 请求太频繁 | 请求过于频繁，已自动等待重试… | 是 | RETRY |
| SERVER_5XX | 服务异常 | 模型服务端异常，已自动重试 2 次。 | 是 | RETRY |
| TIMEOUT | 网络问题 | 模型响应超时，可在「设置」中换更快的模型，或检查网络。 | 是 | RETRY |
| OCR_LOW_CONFIDENCE | 识别不确定 | 屏幕识别置信度较低，请检查屏幕内容是否清晰可读。 | 否 | — |
| PARSE_LOW_CONFIDENCE | 解析不确定 | 对话内容解析不确定，请滚动屏幕重试或手动复制。 | 否 | — |
| PERMISSION_DENIED | 需要授权 | 权限被拒。请在「设置 → 权限引导」中开启所需权限。 | 否 | OPEN_SETTINGS |
| STORAGE_FULL | 存储已满 | 存储空间已满，请到「历史」页清理旧记录。 | 否 | OPEN_SETTINGS |
| CONFIG_INVALID | 配置无效 | 配置无效，请到「设置」检查 API URL / Key / 模型名。 | 否 | CHECK_API_KEY |
| UNCAUGHT | 出错了 | 出现未预期错误，已记录到本地日志，重启后仍异常请反馈开发者。 | 否 | CONTACT_SUPPORT |
| UNKNOWN | 未知错误 | 未知错误，可尝试「重试」或重启 App。 | 否 | — |

## 风险点

- 错误信息泄露内部细节（绝对不能把异常堆栈给用户看）→ ErrorPresenter 已脱敏 + 仅 message
- 错误码与 i18n 文案一致性 → 14 套文案已定制，新增 ErrorCode 需同步
- 降级策略不能影响主流程 → DegradationManager 仅暴露查询 API，调用方按需启用
- CrashLogger 写入可能阻塞 IO → 已 runCatching 兜底失败不抛
- UI 回调 onError 触发可能不在 UI 线程 → 调用方需 handle 线程切换
