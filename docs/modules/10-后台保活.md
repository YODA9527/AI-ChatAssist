# 模块 10 — 后台保活

> 状态：**v0.12 落地** / 优先级 P1 / v0.12.0 模块 10 后台保活（8 核心类 + 36 单测全绿）

## 职责边界

保证 App 在后台时仍能接收用户触发的识别请求：
- **ForegroundService** 常驻（KeepAliveService，specialUse 类型）
- **WorkManager** 兜底（KeepAliveWorker，15min 周期拉活）
- 各 ROM 的拉活策略适配（VendorDetector + VendorGuide 6 厂商自启动引导）

**不负责**业务逻辑。

## 输入输出契约

```kotlin
sealed class KeepAliveEvent {
    object ServiceStarted : KeepAliveEvent()
    object ServiceStopped : KeepAliveEvent()
    data class VendorPushRequested(val vendor: Vendor) : KeepAliveEvent()
    data class RevivedByWorker(val workerName: String) : KeepAliveEvent()
}

enum class Vendor { XIAOMI, HUAWEI, OPPO, VIVO, SAMSUNG, MEIZU, OTHER }
```

## 关键类

- `KeepAliveService`（ForegroundService）
  - 通知常驻
  - `foregroundServiceType="specialUse|systemExempted"`（Android 14+）
  - 自启动管理

- `KeepAliveWorker`（CoroutineWorker）
  - 周期检查服务状态
  - 服务被杀后尝试拉活

- `VendorGuide`（ROM 自启动引导）
  - 检测当前 ROM
  - 引导用户加自启动白名单

## 风险点

- Android 14+ 对 ForegroundService 类型严格审查（已用 specialUse + 描述元数据）
- MIUI 杀后台最凶，必须引导用户加白名单（v0.13 落 UI 入口）
- 华为 EMUI 后台限制 + 鸿蒙无 Google 服务（VendorGuide 已覆盖 huawei systemmanager）
- 三星 One UI 后台管理需要引导（VendorGuide 已覆盖 samsung lool）
- 6 厂商自启动 Intent 路径以官方 ROM 为准，国际版/精简版可能不可解析（已加回退）
- START_STICKY 在 MIUI 上仍可能被强杀（必须引导用户加白名单）
