# 模块 2 — 屏幕文本捕获（混合方案）

> 状态：**v0.3 方向已定** / 优先级 P0
> **决策（2026-07-18）**：无障碍读屏（AccessibilityService）为**首选主通道**，MediaProjection+OCR 为**降级兜底通道**，由 `CaptureStrategyManager` 自动降级 / 恢复。
> 依据：《AI聊天辅助应用-完整开发指南》第 5 章（无障碍优先 + OCR 兜底），推翻 v2「纯 OCR」立场；功能范围仍以 v2 指南（含 v2.1/v2.2）为准。

## 职责边界

统一负责「把当前聊天界面变成结构化文字」这一件事，内部用**双通道**策略：
- **主通道 TEXT_ONLY**：`AccessibilityService` 监听界面节点树，实时提取聊天文本。最快、最省电，对原生 UI 的 App（微信/QQ/Telegram 等）准到飞起。
- **兜底通道 OCR_ONLY**：`MediaProjection` 截图 → ML Kit OCR 提取文字。覆盖无障碍读不到的自绘 UI（抖音 / 小红书等）。
- **混合状态 HYBRID**：降级后每 30s 尝试恢复无障碍，5s 内产出有效结果即切回 TEXT_ONLY。

负责：权限引导（无障碍 + 悬浮窗 + MediaProjection）、前台服务通知常驻、Bitmap 内存回收、双通道生命周期与降级调度。**不负责**聊天语义解析（交给模块 4）。

## 输入输出契约

```kotlin
sealed class CaptureStrategy { TEXT_ONLY; OCR_ONLY; HYBRID }

data class CaptureResult(
    val messages: List<ChatMessage>,   // 已结构化的消息
    val source: CaptureStrategy,        // 本次实际来自哪条通道
    val capturedAt: Long,
)

interface CaptureManager {
    fun start()
    fun stop()
    fun onAccessibilityResult(messages: List<ChatMessage>)  // 无障碍回调
    fun onScreenshotResult(bitmap: Bitmap)                  // 截图回调（走 OCR 通道）
    val captureFlow: SharedFlow<CaptureResult>
}
```

> 原 v2 的 `ScreenCaptureRepository.capture(config): Result<CaptureResult(Bitmap)>` 仍保留，作为 OCR_ONLY 通道内部实现；对外统一收敛到 `CaptureManager` + `captureFlow`。

## 关键类

- `CaptureStrategyManager`（@Singleton）
  - `start() / stop()`
  - `onAccessibilityResult(messages)` / `onScreenshotResult(bitmap)`
  - 降级阈值：连续 3 次空结果 / 连续 3 次低置信度 → 切 `OCR_ONLY`
  - 恢复：OCR_ONLY 下每 30s 探一次无障碍，5s 内有产出切回 `TEXT_ONLY`
- `ChatAccessibilityService`（AccessibilityService）
  - 监听 `TYPE_WINDOW_CONTENT_CHANGED`，遍历节点树提取 TextView 文本
  - 断连自动重连；被杀后由降级逻辑兜底
- `ScreenCaptureManager`（MediaProjection）
  - VirtualDisplay + ImageReader 截图 → Bitmap（OCR 通道）
  - `foregroundServiceType="mediaProjection"`（Android 14+）
- `OcrRepository`（模块 3）：Bitmap → `List<OcrBlock>`，兜底使用

## 风险点

- 无障碍对 Flutter / 自绘 UI（抖音 / 小红书）读不到 → 靠 OCR_ONLY 兜底（已设计）
- 国产 ROM 杀无障碍服务狠 → 降级到 OCR + 30s 恢复探测
- MediaProjection 一次性 Token，进程被杀需重新申请
- Android 14+ 前台服务类型必须正确声明，否则 SecurityException
- 不同 ROM 对截屏 / 无障碍的权限处理差异巨大（MIUI 需单独申请）
